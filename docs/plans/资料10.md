12 号书不是新的需求书，不是新的架构书，也不是 11 号书的附录。它应该被正面定义为：`inkrail runtime implementation WBS and governance plan`，中文可以叫 `inkrail Runtime 实现工作分解与治理计划书`。

## 二、12 号书干什么

12 号书做四件事。

第一，它记录当前源码基线。Inkrail 当前仓库是干净的，`packages/inkrail` 仍然是 specification package。这个包只有 `package.json`、`README.md`、`LICENSE`，没有 `src/`、没有 runtime tests、没有 CLI binary、没有 public library API。根 `pnpm check` 已通过；当前 package dry-run 只发布 LICENSE、README 和 package.json。这是 12 号书必须写入的源状态，不能假装 runtime 已经存在。

第三，它给每个工作包定义审核资格。按照材料体系，一个 work package 必须有目标、上游门槛、上下文闭包、输入事实、文件边界、实施任务、测试任务、验收标准、验证命令、提交规则、审核规则和打回条件。12 号必须逐包写出这些内容。只有这样，后续实现者才能知道本包能改哪些文件、必须读哪些上下文、要跑哪些命令、什么情况必须打回。

## 三、12 号书被谁消费

12 号书的消费者不是普通用户。它主要被四类人消费。

执行者消费它，用来知道每个 work package 的上下文闭包、文件边界、实施任务、测试任务、验证命令和提交规则。执行者不能只看 11 号书就开始写代码，因为 11 号给的是架构事实，不给提交顺序和批次边界。

目标：定义执行规则。

要写：批次状态词：`未开始`、`执行中`、`待审核`、`打回`、`通过`。下一 WP 启动前，前置 WP 必须通过，除非当前 WP 明确无前置依赖。每个 WP 必须有上下文闭包，执行者未读闭包不得开工。每个 WP 必须更新或准备 review package。实际实现时每个 WP 至少一个实现提交和一个审核证据提交；如果某 WP 只创建测试/计划材料，也要明确提交职责。

### 050-global-quality-contract.adoc

目标：定义全局工程质量。

要写：

- `domain core` 不依赖 filesystem/process/Oxigraph/commands/io。
- `services` 组合 core 和 adapters，不格式化 CLI 输出。
- `adapters` 封装外部依赖，不定义 domain identity。
- `commands` 映射 CLI args 到 service input，不持有新鲜度、SPARQL、RDF term 语义。
- `io` 只投影结果，不执行查询。
- public API 是主承载，CLI 是 consumer。
- 所有新增代码必须有对应测试层。
- TypeScript 要 strict，使用 Biome。
- 测试 fixture 放在项目内或 package 内，不跨盘，不丢系统 tmp。
- 新增注释只写代码本身无法表达的 why/invariant，不写表面动作说明。

### 060-global-rejection-conditions.adoc

目标：定义全局打回条件。

必须列出：

- CLI command handler 拥有 domain rule。
- library consumer 必须构造 CLI args 才能查询。
- domain core import filesystem/process/Oxigraph。
- adapter deep import 扩散到 services/core。
- project mode 使用 stale TTL fallback。
- TTL-only mode 声称 project freshness。
- explicit projection 写 `.inkrail/state/`。
- RDF term JSON 把 term 压成字符串。
- Oxigraph Store 暴露给 public API。
- built-in action 改写 08 号查询变量、排序、OPTIONAL、FILTER、GROUP BY、HAVING、property path。
- `--print-query` 触发 project resolve、read TTL、refresh 或 execute。
- review package 写入未运行命令作为 PASS。
- status ledger 写愿望、估计或口头进度。
- 工作包修改边界外文件且不记录受审例外。
